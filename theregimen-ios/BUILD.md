# The Regimen — iOS build

The app is `../app/index.html`. This folder wraps it in a native iOS shell
(Capacitor 8) and is rebuilt from the master; nothing in here edits the app.

Bundle `ai.saltiq.theregimen` · display name *The Regimen* · build 71 (= app v71).

## What is here

| path | what |
|---|---|
| `www/native.js` | The shell. Implements the `window.RUN` contract the app reads (store, health, notifications, rest timer, share). Reads `window.Capacitor` live inside every accessor. |
| `build.mjs` | Copies the master into `www/index.html`, injects `native.js` first, and points the one CDN script (three.js) at `www/vendor/three.min.js` so the 3D vial works offline. Nothing else changes. |
| `www/` | The built web layer. `index.html` = master + those two edits. |
| `ios/` | The Xcode project (generated by `cap add ios`, then: usage strings in `Info.plist`, `App.entitlements` with HealthKit, shared scheme `App`, build number 71). |
| `assets/` → `ios/App/App/Assets.xcassets` | App icon and splash rendered from the formed labs molecule on the app's own dark ground (`#050a12`). |
| `TheRegimen.storekit` | StoreKit test configuration the `App` scheme loads in the simulator: one yearly subscription with a 2-week free intro, product id matching the app. |
| `test-native.mjs` | Exercises the shell against fake plugins. `node test-native.mjs` → 19 checks. |

## No Mac needed — GitHub's Mac builds it

Two workflows in `.github/workflows/` run on GitHub's macOS runners (Xcode 16.4):

| workflow | when | needs | gives |
|---|---|---|---|
| **iOS build (simulator, unsigned)** | every push touching `app/`, `assets/story/` or `theregimen-ios/`; or Actions → Run workflow | nothing | proof the Xcode project compiles; `App.app` and the xcodebuild log as artifacts |
| **iOS to TestFlight** | by hand: Actions → *iOS to TestFlight* → Run workflow (optional build number) | the secrets below | the build uploaded to App Store Connect / TestFlight |

### Secrets for the TestFlight workflow (repo → Settings → Secrets and variables → Actions)

Only Chad can make these; none of them needs a Mac.

1. **Apple Developer Program** membership (developer.apple.com, $99/yr).
2. **App Store Connect → Users and Access → Integrations → App Store Connect API**
   → generate a key with the **App Manager** role. Note the **Key ID** and the
   **Issuer ID**; download `AuthKey_XXXX.p8` (one chance).
   - `APPSTORE_KEY_ID` = the Key ID
   - `APPSTORE_ISSUER_ID` = the Issuer ID
   - `APPSTORE_P8_BASE64` = the file, base64. On Windows PowerShell:
     `[Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\path\AuthKey_XXXX.p8"))`
3. **developer.apple.com → Membership** → `APPLE_TEAM_ID` (10 characters).
4. **App Store Connect → Apps → +** → new app, bundle id `ai.saltiq.theregimen`,
   name *The Regimen*. (The bundle id first has to exist under Certificates,
   Identifiers & Profiles → Identifiers, with HealthKit and In-App Purchase ticked.)
5. Run the workflow once **without** a `.p12`. With the API key, Xcode creates
   the provisioning profile itself and will try to mint an *Apple Distribution*
   certificate. If the archive log says it could not (Apple limits who may
   create certificates by API), make the certificate on Windows:

   ```
   openssl genrsa -out dist.key 2048
   openssl req -new -key dist.key -out dist.csr -subj "/emailAddress=you@example.com/CN=The Regimen/C=US"
   ```
   developer.apple.com → Certificates → + → **Apple Distribution** → upload
   `dist.csr` → download `distribution.cer`, then:
   ```
   openssl x509 -in distribution.cer -inform DER -out distribution.pem
   openssl pkcs12 -export -inkey dist.key -in distribution.pem -out dist.p12 -password pass:CHOOSE_ONE
   ```
   - `IOS_DIST_P12_BASE64` = `dist.p12`, base64 (same PowerShell line as above)
   - `IOS_DIST_P12_PASSWORD` = CHOOSE_ONE

   Keep `dist.key` somewhere safe; it is the only copy.

6. Run **iOS to TestFlight**. Ten to fifteen minutes later the build is in
   App Store Connect → TestFlight; add yourself as an internal tester and it
   installs on the phone through the TestFlight app.

## What the shell does and does not do — read from the plugins' own source

| RUN member | plugin | status |
|---|---|---|
| `store.buy/restore` | cordova-plugin-purchase 13 (StoreKit) | wired; needs the product in ASC or the .storekit file in the simulator |
| `health.connect/read` | @capgo/capacitor-health 8 | reads weight, body fat, steps, workouts |
| `health.pushWeight`, `pushComposition` (body fat) | same | writes (`saveSample`, any HKQuantityType) |
| `health.pushWorkout`, lean mass | same | **not supported by the plugin** — returns `{ok:false}`; the app's "every session goes back to Health" line is not true on device until a small native method is added |
| `notify.schedule/cancel`, `restNotify` | @capacitor/local-notifications 8 | wired; taps route to the app's `onNativeAction` |
| `share` | @capacitor/share 8 | wired |
| `labs` | — | `null` on purpose: the app's `<input type="file" capture>` path works in WKWebView; the scan contract needs a text reader the app does not expose |
| `rest` (Live Activity), `watch`, `ai` | — | absent; the app falls back (in-page timer, its own AI service) |

## What actually worked — 20 Sep 2026 (first upload)

Automatic signing does **not** work on a team with no registered device: `xcodebuild archive` insists on a development profile, and a distribution identity cannot be forced under `CODE_SIGN_STYLE=Automatic`. The path that uploaded:

1. The App Store Connect API key (App Manager) — `APPSTORE_KEY_ID`, `APPSTORE_ISSUER_ID`, `APPSTORE_P8_BASE64`, `APPLE_TEAM_ID`.
2. A private key and CSR with openssl on Windows (`C:\Users\ChadDerocher\Documents\apple-keys\`), then `asc-provision.mjs` in that folder creates the **Apple Distribution certificate** and the **App Store profile** through the API (`POST /v1/certificates`, `POST /v1/profiles`) — no browser, no Mac.
3. `openssl pkcs12 -export` → `dist.p12`; secrets `IOS_DIST_P12_BASE64`, `IOS_DIST_P12_PASSWORD`, `IOS_PROFILE_BASE64` (the profile, base64) — set with `gh secret set` piped from the files, never printed.
4. The workflow installs the profile under `~/Library/MobileDevice/Provisioning Profiles/<UUID>.mobileprovision` and signs archive **and** export with `CODE_SIGN_STYLE=Manual`, `CODE_SIGN_IDENTITY="Apple Distribution"`, `PROVISIONING_PROFILE_SPECIFIER="The Regimen App Store"`; ExportOptions carries `signingStyle manual` and the bundle → profile map.
5. `runs-on: macos-26` — App Store Connect refuses anything built with an SDK older than iOS 26 (Xcode 26).

The certificate and profile expire 20 Sep 2027; re-run `asc-provision.mjs` (a new CSR is fine) and reset the three secrets. GitHub Actions needs a card on the account and an Actions budget above $0 (it is $20/month with a hard stop).
